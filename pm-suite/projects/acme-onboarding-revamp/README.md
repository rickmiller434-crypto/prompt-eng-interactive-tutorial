# Example — Acme Onboarding Revamp

A worked example demonstrating the PM Suite end-to-end on a fictional but realistic project.

## Project synopsis

**Acme Logistics**, a mid-market logistics-SaaS company, currently takes 14 days median for new customers to reach first-value, with a 28% drop-off in the first 30 days. The project aims to **redesign onboarding** so median time-to-first-value falls to ≤ 5 days and 30-day drop-off falls to < 15%.

- **Duration:** Feb 2026 – May 2026 (4 months)
- **Sponsor:** VP Customer Success
- **Team:** 8 (PM, Senior PM, 2 designers, 3 engineers, 1 data analyst — plus Customer Success liaison)
- **Budget envelope:** $480k (incl. 12% contingency)
- **Lifecycle:** **Hybrid** — predictive backbone for data-privacy / compliance gating and reporting; adaptive delivery for the UX & product work in 2-week increments.

## How to read this folder

The files here are the artifacts the suite would actually produce during a run of this project. Read them in roughly this order to follow the lifecycle:

1. `tailoring.md` — intake + Tailoring Record (produced by `pm-tailor`)
2. `charter.md` — project charter
3. `business-case.md` — benefits register and value hypothesis
4. `stakeholder-register.md` + `engagement-matrix.md` — produced by `pm-stakeholders`
5. `risk-register.md` — produced by `pm-uncertainty`
6. `product-backlog.md` — produced by `pm-planning`
7. `decisions/decision-log.md` — running record, owned by `pm-work`
8. `status-reports/2026-03-15-status.md` — produced by `pm-measurement` mid-flight
9. `audits/audit-2026-03-15.md` — produced by `pm-principles-auditor` mid-flight
10. `closure/lessons-learned.md`, `closure/benefits-realization.md`, `closure/closure-report.md` — produced at closure

## What this example does and does not show

- ✅ Shows: how artifacts trace value → stakeholder → backlog → delivery → benefit
- ✅ Shows: how hybrid lifecycle blends adaptive delivery with predictive governance
- ✅ Shows: how the principles auditor produces evidence-cited findings
- ⚠️ Simplified: only a representative slice of each artifact is filled in (real projects would have many more rows in each register, more backlog items, more decisions)
- ⚠️ Not shown: live tool integrations (Notion / Jira / GitHub Projects) — those land in Phase 6
